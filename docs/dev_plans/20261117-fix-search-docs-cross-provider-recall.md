# `search_docs` misses cross-provider additions (speaker diarization, 1.16)

## Status

Planned. Investigation done; the cause is **not** yet verified (Phase 0). Branch `fix/search-docs-cross-provider-recall`. Split out of #166 (closed); no issue filed yet (Phase 0 files it).

Revised 2026-11-18 after three `/review-plan` rounds (38, 47 and 37 findings). Three decisions came from a grill on 2026-11-18 and are marked "Decision (grilled)". Rounds 2 and 3 asked for every finding to be fixed without a further grill, so their open design choices are marked "Decision (author)": the author picked a default and a reviewer should confirm or overturn each one.

## Goal

For every page in the set **Q** of STT pages that hold diarization text, `search_docs("speaker diarization speaker_format", limit=20)` returns at least one **qualifying hit** from that page, with the reranker on **and** off. A *qualifying hit* is a chunk of that page whose full text contains `speaker_format` or `diarize`. Phase 0 enumerates Q and the qualifying chunk ids from `get_doc`; on the live index Q holds at least twelve pages (AssemblyAI, AWS, Deepgram, ElevenLabs, Meta, NVIDIA, OpenAI, Smallest AI, Soniox, Speechmatics, xAI, Zoom AI).

Decision (author): the Goal is coverage of Q at `limit=20`, not "five named providers at `limit=10`", for two reasons the review measured. (1) The source of the five is unverified: the indexed 1.16.0 changelog (`CHANGELOG.md`, lines 132-134) adds diarization only to ElevenLabs, AWS Transcribe and OpenAI, and groups Deepgram and Soniox with xAI, Smallest AI, Meta and Zoom AI ("now report the diarization speaker", lines 142-145). Q covers all of them, so the Goal no longer depends on that list. (2) With the reranker on, twelve Settings chunks tie at score 0.0000 and no query-independent signal prefers five of them, and a simulated per-page cap on the live list still leaves ElevenLabs as page 12 (reranker on) or Soniox as page 12 (reranker off) at `limit=10`. Eight distinct pages already fill the top ten. Phase 0 records `limit=5` and `limit=10` results but does not gate on them.

If Phase 0 shows no fix reaches this within the Invariant's budget, we record why and ship the documented limitation instead.

## What we know

Verified 2026-11-17 against the index then (framework 1.16.0). The index was rebuilt on 2026-11-18 (`last_refresh_at` 2026-11-18T07:50) and Soniox now ranks 8 with the reranker on, so **Phase 0 re-takes every number below** and records `last_refresh_at` beside each.

- **Not a content gap.** The content is indexed and readable via `get_doc`: `speaker_format` / `diarize` rows in `stt/elevenlabs.md` (lines 81-82), `stt/aws.md` (82-83), `stt/openai.md` (101, 121), `stt/deepgram.md` (121, 136), `stt/soniox.md` (104-105); `TranscriptionFrame.speaker` in `frames/data-frames.md` (173-177); the RTVI `speaker` field in `standards/rtvi-standard.md` (374-383). `stt/gladia.md` has none, which is correct.
- **The right chunks are retrieved but ranked below the limit.** With the reranker off, the "ElevenLabs / OpenAI / AWS Transcribe Speech-to-Text Settings" chunks rank 9-11, behind Speechmatics (x3), AssemblyAI, NVIDIA (x3) and Meta. A caller using a small `limit` sees only the first five.
- **The cross-encoder pushes them further down.** With the reranker on, the same chunks come back at ranks 10-18 with score `0.000` (sigmoid of a strongly negative logit, `cross_encoder.py:111`), under a top five scoring 0.92-0.999.
- **Concept decomposition helps only partly.** `"speaker diarization + speaker_format"` surfaces OpenAI, Zoom AI and `data-frames.md` in the top 14, but still not ElevenLabs, AWS, Deepgram or Soniox.
- **The split is by chunk kind, not by provider** (live index, 2026-11-18). With the reranker on, ranks 1-6 are prose sections (`section: null`, e.g. a "Speaker Diarization" section for Speechmatics); ranks 7-19 are "Settings" table chunks for 12 providers, all scoring 0.0000. Phase 0 confirms it per hit.
- **Code facts** (read 2026-11-18; Phase 0 re-confirms with the real tokenizers):
  - The cross-encoder scores `r.chunk.content[:1000]` (`services/retrieval/cross_encoder.py:97`) for only the top `top_n` = 20 candidates; the rest keep RRF-scale scores after the sigmoid-scale ones (`cross_encoder.py:116-117`). Its model input is capped at 512 tokens (`services/onnx_backend.py:73`, `_CROSS_ENCODER_MAX_SEQ`), and the query counts against the cap.
  - **Measured on the live index** (read-only, 2026-11-18): the 512-token ceiling sits at character 2007 (ElevenLabs), 2153 (OpenAI), 2035 (Deepgram), 1397 (AWS) and 1087 (Soniox) of each Settings table chunk. The first 1000 characters are 367-475 tokens. `diarize` first appears at character 2285 in ElevenLabs (past the ceiling) and 1863 in Deepgram (inside it); the diarization text starts at token 535, 506, 468, 709 and 711 for ElevenLabs, OpenAI, Deepgram, AWS and Soniox. So a character window of about 2000 would reach Deepgram, sit on the edge for ElevenLabs and OpenAI, and miss AWS and Soniox.
  - **Table markup dominates the token budget.** The separator row alone costs 317-457 tokens because WordPiece emits one token per dash; header plus separator is 650-930 characters before any data row, and each data row is 325-465 characters. Today's embedding of a table chunk holds the header and about 245 dash tokens and **no data row**. Cell padding adds whitespace characters but few tokens.
  - The bi-encoder embeds at most 256 tokens (`onnx_backend.py:72`, `_DEFAULT_MAX_SEQ`, tokenizer truncation on). Doc chunks are sized to `doc_max_tokens` = 512 at 4 characters per token (`shared/config.py:105`, `docs_crawler.py:28`), about 2048 characters. Text late in a chunk never reaches the vector leg.
  - `_chunk_section` (`docs_crawler.py:178`) returns a section of at most about 2048 characters as one chunk before its paragraph loop, then splits only on blank lines, so a markdown table is one paragraph and one chunk even above 2048 characters. The ElevenLabs settings table is 2933 characters with `diarize` at 2285 and `speaker_format` at 2611.
  - Table chunks carry no heading or provider name in `content`: the ElevenLabs `## Settings` heading and intro are a separate 278-character chunk, and the table chunk starts at `| Parameter`. Title and section live only in metadata (`docs_crawler.py:265-267`); the embedding (`embedding.py:79`) and the cross-encoder (`cross_encoder.py:97`) see `content` alone.
  - `_apply_diversity` (`services/retrieval/rerank.py:334`) is a **no-op for docs-site hits**. `_would_violate` (`rerank.py:384-395`) checks the repo before the path, and docs-site chunks carry no repo (7576 of 7581 doc chunks on the live index; `docs_crawler.py:272-280`), so after three placements every such candidate "violates" and the loop force-places the next one in score order (`rerank.py:415-421`). The few README-fallback chunks are `content_type="doc"` but do carry a repo (`cli.py:1427-1429`), so it does limit those. The cross-encoder then re-sorts the top 20 anyway. No per-page limit exists for docs-site hits at any stage.
  - FTS ANDs every query token (`services/index/fts.py:628-640`), so a chunk missing one token gets no keyword rank and no dual-hit bonus.
- **Reranker default.** `RerankerConfig.enabled` defaults to `True` (`shared/config.py:181-182`). `serve` and the CLI run reranker-off when the config disables it, when the model is not cached (`shared/reranker.py:32`, `probe_reranker`), or at runtime when the model fails to load (`shared/reranker.py:58-77`, `runtime_reranker_reason`). `probe_reranker` deliberately never returns `load_failed` (`shared/reranker.py:10-19`): the model loads lazily on the first `_score` call (`cross_encoder.py:87-91`) and `hybrid.py:208` then skips the reranker silently. The `RerankerConfig` docstring ("Disabled by default", `config.py:178`) and the `AGENTS.md` Review Checklist entry "**[Logic] won't-fix**: Confidence scores are optimistic on weak `search_examples` results" (2026-03-24, which says the cross-encoder is "disabled by default") are stale. Phase 1 fixes both.
- **Unknown:** the `limit` the reporter used; whether the provider rows are even *queried* by a user phrasing other than the forms in the Measurement set.

## Architecture & Call Flow

Two processes touch the candidate fixes.

```
refresh process (ingest)                    serve / CLI process (query)
-------------------------                   -----------------------------------------------
llms-full.txt                               query
 -> docs_crawler._chunk_section                -> decompose (" + " / " & " concepts)
 -> chunks (<= ~2048 chars)                       per concept: _rerank_raw(limit=per_concept)
 -> embed (<= 256 tokens) + FTS index             -> vector leg (embeds <= 256 tokens)  \
 -> store (Chroma + SQLite)                       -> FTS leg (AND of all tokens)         -> RRF
 skip marker: docs:content_hash                   -> heuristics (symbol boost, dual-hit bonus)
 (hash of raw llms-full.txt only,                 -> _apply_diversity (no-op for docs-site hits)
  cli.py:131, 1410-1413)                          -> cross-encoder: top_n=20, content[:1000],
                                                      512-token cap, re-sorts by own score;
                                                      the unscored tail keeps RRF-scale scores
                                                -> multi-concept only: round-robin merge,
                                                   dedupe by chunk_id (hybrid.py:216-316)
                                                -> [:limit]  (hybrid.py:214)
                                            get_doc: joins a page's chunks with blank lines
                                                     (hybrid.py:406); doc_id path returns one chunk
```

`_rerank_raw` (`hybrid.py:186`) serves `search_docs`, `search_examples`, `search_api` and `get_code_snippet`; anything changed at the cross-encoder or diversity stage is shared by all four. `_rerank_raw` slices to `limit` itself and `_multi_concept_search` passes it `per_concept` = ceil(limit / n concepts), so a post-merge cap would see at most about `limit` hits and promote nothing: branch D must change this seam (see D).

## Invariant

Decision (grilled): a change must keep the expected hit of every query in the regression set R (below) inside its current top 10, reranker on and off. A rank drop that stays inside the top 10 is allowed; a fall out of it fails. The candidate fixes necessarily move other results, so "must not lower rank" is not absolute; a fix that cannot meet this bound ends as the limitation outcome.

**Expected hit.** Decision (author): Phase 0 picks one explicit (repo, path) or chunk id per query in R and records it in the results file as a table of query, tool, expected hit, source. A multi-concept query gets one expected hit per concept. A smoke item that names a property, not a result (for example items 8, 9, 33), is gated on that property instead of a rank. The R rank capture runs at `limit=10` (the quality cases themselves run at `limit=5`). `get_code_snippet` has no top 10, so its queries are held to the smoke item's own pass/fail.

**Mechanical gate from the benchmark.** The quality benchmark does not use `required_failures`: `strict_mode = not extra_repos` (`test_retrieval_quality.py:479`) is off on any index with extra repos (the live index has 73 repos against 3 defaults), a missed threshold is then logged as `WARN`, not `FAIL` (line 391), and `required_failures` (line 488) stays empty. `threshold_met` alone is also too weak for `search_docs` cases: `_evaluate_search_docs` averages hits, confidence and concepts (lines 255-261), so a case with zero alias coverage scores `round(2/3, 2)` = 0.67 and still meets the 0.67 minimum (lines 64, 388). Decision (author): the gate compares, before and after, the per-case `score`, `threshold_met`, `parts` (including `concepts`) and `matched_alias_groups` from the JSON report (`PIPECAT_HUB_BENCHMARK_OUTPUT`; Phase 0a makes sure the report carries all four): no `threshold_met` may flip true to false, no case's `matched_alias_groups` may shrink, and no `concepts` part may fall. Phase 0 lists the cases that are already below threshold at baseline. For `search_docs` cases the rank gate above is the stronger check; this gate catches the rest.

**Noise rule.** Phase 0 runs the baseline twice on F. Decision (author): if the two runs differ in any top-10 path, stop and find the cause before any branch work; otherwise any fall out of a top 10 fails.

## Measurement set

Queries (each run with the reranker on and off, at `limit` 5, 10 and 20):

- **Q1** `search_docs("speaker diarization speaker_format")` (the Goal query).
- **Q2** `search_docs("speaker diarization + speaker_format")` (multi-concept form).
- **Q3** `search_docs("<Provider> speech-to-text diarization")` for each of ElevenLabs, AWS Transcribe, OpenAI, Deepgram, Soniox (the per-provider workaround).
- **Q4** `search_docs("Speechmatics speaker diarization")` (a control that works today).

Decision (author): per-query criteria, with baselines recorded in the results file. Q1: the Goal. Q2: the number of Q pages with a qualifying hit in the top 20 does not fall below its baseline. Q3: each provider's qualifying hit stays in its baseline top-5 membership. Q4: the Speechmatics qualifying hit keeps its baseline rank within the top 3, and the count of Speechmatics-page chunks in its top 5 and top 10 does not fall below baseline (this is what branch D's page cap could break).

Regression set **R**: every case in `_QUALITY_CASES` (`tests/benchmarks/test_retrieval_quality.py`, run by `just benchmark-quality`) plus the `search_docs`, `search_examples` and `search_api` queries in `docs/smoke-test.md`. If a fix is scoped to doc hits only, R may drop the examples and API queries; a fix at the shared cross-encoder seam keeps them.

**One corpus.** Decision (author): every before/after comparison runs against a single frozen index **F**, the Phase 0 backup copy, never the live index, so the corpus cannot drift between runs. After a code-only fix (D, A) the "after" is F again with the fix applied. After an ingest fix (B), re-ingesting fetches the live `llms-full.txt` and re-fetches every repo, so the comparison is against a **control re-ingest** (below), not against F, and both runs must show the same `docs:content_hash` and the same `repo:*:commit_sha` markers. The live index is measured once at the end as a sanity check only, and labelled as such. A fix that passes on F must also pass that final live check, which is a different build of the index.

### Phase 1: the fix chosen in Phase 0, or the documented limitation

**Exit rule.** If the Invariant or the latency budget fails in Phase 1 on F, return to Phase 0 step 7, take the next branch in order, and record the failure and the new pick in the results file before continuing.

Every branch's unit tests use **real chunk text frozen from the Phase 0 results file**, not synthetic text, plus the synthetic edge cases listed. Every branch that changes retrieval also adds `tests/benchmarks/live_trace.py` changes where it needs a new stage column (post-cap, per-window), so its "after" numbers come from code that includes the fix.

- **D (page cap).** `services/retrieval/hybrid.py` (`_rerank_raw` and `_multi_concept_search`), `services/retrieval/rerank.py` (adds a new cap function; `_apply_diversity` is unchanged), `tests/benchmarks/live_trace.py`. Decision (author) on the seam: `_rerank_raw` stops slicing to `limit`; it returns the full cross-encoded list and its callers slice. The single-query path applies the cap then slices at `hybrid.py:214`. The multi-concept path applies the cap to each concept's full list before taking `per_concept` hits, then again after the round-robin merge and `chunk_id` dedupe, then slices. Decision (author) on the cap: it is a **stable reorder inside the cross-encoder-scored window** (the first `top_n` positions): the first hit of each page, keyed by (repo, path), keeps its score order and each page's later hits move behind them within that window; the unscored tail stays after it, so scores of the two scales are never reordered against each other. It never fills then backfills and it does not rewrite scores (`DocHit.score` may be non-monotonic across the scored/unscored boundary today and stays so). A doc hit is a chunk with `content_type == "doc"`. Tests: frozen real candidate list; edge cases (fewer pages than `limit`, ties, a single page, README-fallback chunks that share the path `README.md` across repos); a case where one page holds the top three relevant chunks (the floor on Q3/Q4 target-page chunks from the Measurement set); `limit=5` is a prefix of `limit=10`; a Q2 multi-concept case; `search_examples`, `search_api` and `get_code_snippet` results unchanged by the cap; `evidence` confidence (max and mean of returned scores, `evidence.py:57-64`) recorded before and after on R; reranker on and off; rerun smoke item 52.
- **A (window).** `services/retrieval/cross_encoder.py`, `shared/config.py` (`RerankerConfig`: a window size in characters and a window count), the `CrossEncoderReranker` construction sites that must pass them (`cli.py:971` and `cli_query.py:317`; `cli.py:1301` only pre-downloads the model and needs nothing), an env var with a row in `docs/configuration.md`, `tests/benchmarks/live_trace.py`. Decision (author): windows are sized in **characters** from the worst-case characters-per-token ratio measured in Phase 0, so `onnx_backend.py` and its private tokenizer stay untouched; the 512-token cap includes the query, so the size leaves room for it. Tests: frozen real table chunk; chunk shorter than the window, match at the boundary, match beyond it; the 512-token ceiling is respected on the frozen table chunks, using the real cross-encoder tokenizer (skipped when the model is not cached); the setting reaches the reranker from config; the model-call count equals `top_n` x windows; one model-backed test that the best-window score of a frozen target chunk beats its first-window score (skipped when the model is not cached); latency within the Phase 0 budget via `live_trace.py`; reranker on and off; smoke item 52.
- **B (ingest).** `services/ingest/docs_crawler.py` (`_chunk_section`, `chunk_markdown`), `services/retrieval/hybrid.py` (`get_doc`), `cli.py` (skip marker), the chunker-version constant in `docs_crawler.py`. Decision (grilled): split only table paragraphs too big for the embedding window; prose chunks and small tables stay untouched; `doc_max_tokens` does not change. The rules the reviews added, each a Decision (author):
  - **B1, compaction first.** The chunker rewrites each markdown table so the separator row is one `---` per cell and runs of padding spaces inside cells collapse. The result is still a valid markdown table, so `get_doc` shows it unchanged in meaning. Phase 0 measures whether compaction alone brings the first data row inside both windows; only then is B2 needed.
  - **B2, split trigger and sizing.** One trigger: a table paragraph longer than the group budget, measured **after** compaction. The budget is a **character** count chosen in Phase 0 from the measured compacted characters-per-token ratio, so `services/ingest` takes no dependency on the embedding tokenizer. A Phase 1 test asserts, with the real tokenizer (skipped when the model is not cached), that every group of every frozen target table is at most 256 tokens.
  - **Boundary.** The split runs **before** `_chunk_section`'s early return (a table of 1024-2048 characters must split too). Each row group is its own chunk, is never packed with neighbouring paragraphs and gets no overlap. Prose before the table stays in its own chunk.
  - **Context.** Each group's `content` starts with one non-heading context line (page title and section heading, plain text so `heading_titles(content)` does not read it as a section), then the header row and separator, so the embedding and the cross-encoder see the provider name. Phase 0 step 4 records which target chunks lack it today.
  - **Markers and `get_doc`.** The chunker writes metadata on **every** group, the first included: a flag marking the context line and a group index; groups after the first also carry `table_continuation: true`. `get_doc` joins consecutive continuation chunks with a single newline and strips the context line, repeated header row and separator from every group, so a rebuilt page shows each table as one table with one header. The `doc_id` path returns one chunk unchanged, context line and header included. A new `get_doc` against an old, unflagged index behaves as today.
  - **Skip marker.** Keep `docs:content_hash` the **raw** hash of `llms-full.txt` so older installed tools keep working. ## Risk

Retrieval changes shift ranking for unrelated queries; that is why Phase 0 comes first and why "limitation" is an acceptable outcome. The cross-encoder stage is shared by `search_docs`, `search_examples`, `search_api` and `get_code_snippet`, so a change there is judged against R for all four unless scoped to doc hits. An ingest-side change needs the `docs:chunker_version` pair, a changelog note including the downgrade step, and a re-measurement on scratch data directories so the "before" index is never overwritten.
